# «Карточки»: продуктовая задача и решение

Обновлено 9 сентября 2026 после уточнения владельца продукта. Цель вкладки — быстро создавать и редактировать контент большого каталога: описания, rich-контент и изображения. Основные действия — генерация, массовые правки через Excel и оперативное редактирование на сайте.

## Что исправлено в понимании задачи

Предыдущая версия делала главным сценарием диагностику воронки, приоритеты и согласование изменений. Это смещало внимание с повседневной работы с контентом. Пользователь явно указал, что центром должны быть карточки и инструменты их подготовки. Поисковая аналитика полезна как материал для описаний.

Выбран табличный каталог с быстрыми правками, редактором карточки и общим выбором товаров для массовых действий. Генерация, инфографика и Excel доступны отдельными разделами в одном рабочем пространстве. Для небольших изменений не нужно проходить многоступенчатое согласование.

## Какие запросы подтверждены

Следующие потребности сформулированы владельцем продукта, а не выведены из рыночной статистики:

| Потребность | Реализация |
| --- | --- |
| Быстро менять описания | Редактирование в строке и расширенный редактор |
| Создавать контент карточек | Генерация для выбранных товаров или списка новых названий, предпросмотр |
| Работать с rich-контентом | Блоки текста и изображений, порядок, предпросмотр, JSON |
| Генерировать инфографику | Настройка макета, собственное фото, предпросмотр, PNG, добавление в галерею |
| Менять много карточек | Выбор по фильтру, массовая правка поля, XLSX с проверкой строк |
| Использовать поисковые запросы | Отдельный вспомогательный раздел с источником и доступностью WB API |

Дополнительные гипотезы: единый стиль изображений на коллекцию, повторное использование настроек генерации, очередь заданий с частичными ошибками и повтором. Частота этих потребностей и готовность платить не измерены; интервью с продавцами в этой задаче не проводились.

## Что есть на рынке

Ниже — возможности по публичным страницам самих сервисов; платные кабинеты и качество генерации не тестировались.

| Решение | Что подтверждено | Значение для продукта |
| --- | --- | --- |
| Wildberries | Собственный редактор rich: текст, фото, видео, генерация. [Инструкция WB](https://seller.wildberries.ru/instructions/ru/ru/material/rich-content?recommended=true) | Само наличие генератора не создаёт отличия; ценность нужно проверять на скорости работы с каталогом |
| MPSTATS | SEO-инструменты, запросы, сравнение карточек и AI-описания. [SEO-модуль](https://mpstats.io/instruments/seo-optimization) | Поисковые данные должны помогать редактировать релевантный текст |
| MP Manager | Работа с контентом и характеристиками, автоматизация и поисковые инструменты. [Платформа](https://mpmgr.ru/) | Единое окно уже ожидаемо; важны непрерывный сценарий и понятные массовые операции |
| SELLER MOON | A/B-тестирование фотографий. [Описание](https://sellermoon.ru/news/ab-photo) | Проверка результата изображения — возможное развитие после создания и применения контента |

Мы не утверждаем, что у конкурентов отсутствуют аналогичные массовые операции или аудит. Продуктовая гипотеза MarginPilot: сократить переключения между генератором текста, редактором изображений, Excel и кабинетом WB.

## Решение интерфейса

1. **Каталог** — рабочая таблица. Название и описание можно править прямо в строке; rich и изображения открываются на нужной вкладке редактора.
2. **Генерация** — выбрать товары и типы контента, указать факты, посмотреть результат, сохранить. Для новых товаров — список названий.
3. **Инфографика** — настроить изображение, проверить и применить к товару или выбранному набору.
4. **Excel** — выгрузить, изменить, загрузить, проверить строки и различия, применить корректные изменения.
5. **Поисковые запросы** — фразы для собственного ассортимента. Отсутствие подписки не блокирует редактор.

Правки локальные и версионируемые. Массовое сохранение атомарно: ошибка одного элемента не оставляет половину пакета применённой. При импорте пользователь сначала выбирает корректные строки, после чего выбранный пакет применяется целиком.

## Можно ли получать поисковые запросы через WB API?

Да. Нужны токен категории «Аналитика» и подписка «Джем». API возвращает поисковые запросы по товарам продавца.

- POST /api/v2/search-report/product/search-texts — топ запросов по товарам: до 30, на тарифах «Продвинутый» и «Премиальный» — до 100.
- POST /api/v2/search-report/product/orders — заказы и позиции по дням; запрашиваемый интервал до 7 дней.
- Данные доступны в пределах последних 365 дней.
- Для больших объёмов есть CSV-отчёты, включая SEARCH_QUERIES_PREMIUM_REPORT_TEXT; доступ зависит от тарифа.

Источники: [официальная инструкция поиска](https://dev.wildberries.ru/knowledge-base/articles/019d49a4-0f6a-70bb-a87b-c1237a1a0714), [Analytics API](https://dev.wildberries.ru/en/openapi/analytics), [CSV-отчёты](https://dev.wildberries.ru/knowledge-base/articles/019d49a3-f76b-7f22-82f3-54930b8f59e8/analitika-prodavtsa-csv).

Это данные собственного ассортимента, а не произвольная база рыночных запросов и частотности. В реальном продукте следует показывать период, дату обновления и причину отсутствия данных. В моке фразы синтетические.

## Что проверять дальше

Уточнение 10 сентября: создание настраивается независимо от источников. Добавлены режимы «описание», «изображения», «оба», произвольные характеристики и отдельные переключатели четырёх типов результата. Фото партии привязываются к товарам, настройки количества rich-блоков и инфографики применяются к каждому товару. Название и описание можно исправить до сохранения; характеристики — в редакторе после создания. Мок не распознаёт визуальные свойства: для этого предусмотрен заменяемый сервис генерации.

Для UX: время изменения 50 описаний; доля строк, успешно прошедших Excel-цикл; время подготовки набора изображений; способность заметить ошибку до применения; восстановление после конфликта версии.

Для качества AI: фактическая точность, отсутствие придуманных свойств и расхождений между изображением и реальным товаром, полезность rich-блоков. Шаблонный генератор мока не подтверждает качество будущей модели.

Для переноса: серверный repository, хранение медиа, очередь генерации, авторизация, маппинг Content API и публикация с проверкой результата. Публичный API записи rich-контента не подтверждён — этот путь нужно исследовать отдельно. [Устройство и ограничения мока](./README.md).
