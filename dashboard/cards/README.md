# Карточки — центр работы с контентом

Открыть: [локальный мок](http://127.0.0.1:8001/dashboard/#cards). [Продуктовое решение и источники](./analysis.md).

## Рабочие сценарии

- Каталог с поиском по названию и артикулам, фильтрами, страницами по 20 товаров и выбором всех результатов фильтра.
- Быстрая правка названия и описания прямо в таблице. Массовая правка текстового поля с просмотром изменений до применения.
- Редактор: название, описание, состав, замеры; rich-блоки с текстом и изображением; галерея с загрузкой, порядком и удалением изображений.
- Генерация по описанию, изображениям или их сочетанию. Название, описание, rich-контент и инфографика включаются независимо; создание до 1 000 локальных карточек списком. Можно создать карточку без генерации.
- Категория, бренд, артикулы, состав, замеры и произвольные характеристики с сохранением в карточку. Отдельная вкладка редактора для дальнейших правок характеристик.
- Студия инфографики: товар, заголовок, подпись, палитра и шаблон; использование загруженного фото, добавление результата в одну или выбранные карточки, скачивание настоящего PNG 900 × 1200.
- Описание товара для инфографики подставляется из карточки и редактируется отдельно. Вместе с характеристиками, пожеланиями, палитрой и текстом изображения оно формирует промпт. Доступны копирование и TXT; точный промпт сохраняется в данных изображения. При массовой генерации описание остаётся индивидуальным для каждого товара.
- Реальный XLSX: выгрузка, редактирование вне сайта, загрузка, проверка строк, просмотр различий, применение выбранных корректных строк.
- Поисковые запросы как вспомогательный источник для текста. Демо состояний без подписки «Джем» и без доступа к аналитике.
- Локальная история версий, восстановление после перезагрузки, проверка конфликтов версий, защита несохранённого редактора.

Правки сохраняются в локальный черновик сразу. Отдельного обязательного согласования каждой правки в этом сценарии нет. Статусы и товары синтетические; публикации на WB не происходит.

Старый workspace.js больше не подключается: это предыдущая версия с диагностикой. Старые обработчики в dashboard/index.html сохранены вместе с существовавшими пользовательскими изменениями; при переносе нового модуля они не нужны.

```js
import React from 'react';
import { createCardsWorkspace } from './cards/content-workspace.js';
import './cards/workspace.css';
import './cards/content-workspace.css';

const CardsWorkspace = createCardsWorkspace(React, realContentRepository, generationService);
// Объявить один раз, вне render:
// <CardsWorkspace initialQuery="" />
```

React передаётся параметром, JSX и сборщик для локального просмотра не нужны. Подключите SheetJS как window.XLSX (в текущей оболочке уже есть), шрифты Onest/JetBrains Mono и Material Symbols либо замените иконки. DTO не зависят от транспортных схем WB.

Repository внедряется вторым аргументом. Его асинхронные методы возвращают полный снимок, ошибки отклоняют Promise. saveBatch проверяет version и применяет пакет целиком либо отклоняет целиком. createMany также атомарен. Для реального сервера сохраняйте эти свойства.

Третий необязательный аргумент — GenerationService с методом generate(cards, options), возвращающим массив изменений или Promise. По умолчанию используется шаблонный generateContent. buildGenerationRequest отделяет характеристики, выбранные источники и настройки результата. Используйте его в адаптере серверной генерации; токены модели не должны попадать в браузер. Отдельная студия использует makeImage, её генерацию нужно подключить к серверу отдельно.

## Настраиваемое создание

Источники: только описание, только изображения или оба. Неактивный источник исключается из запроса; исходные фото и текст не очищаются при переключении. Для существующего товара можно использовать его текущее описание и галерею. Новые фото привязываются к конкретному товару; незаполненная или устаревшая привязка блокирует генерацию.

Состав результата задаётся отдельно: любое сочетание названия, описания, rich и инфографики. Настраиваются стиль текста, 1–6 rich-блоков, 1–5 изображений, шаблон и палитра. Для существующих карточек медиа и rich по умолчанию дополняются; можно явно выбрать замену. Для новых товаров отключение всех результатов означает ручное создание без генерации.

Характеристики представлены расширяемым списком name/value, до 100 полей. Есть подсказки для цвета, размеров, сезона, страны, комплектации, упаковки и баркодов. Это локальная форма, не полный справочник обязательных полей WB: в реальном проекте подгружайте схему выбранного предмета с типами, единицами, обязательностью и отдельными SKU размеров. В списковом создании характеристики общие для партии; индивидуальные значения редактируются в карточках после создания.

Название можно оставить пустым: в моке появится «Новый товар», либо заголовок из исходного текста при включённой генерации названия. Название и описание редактируются в предпросмотре. При изменении исходных данных или настроек прежний результат сбрасывается, чтобы не сохранить устаревший контент.

## Excel

Лист «Карточки»: ID, версия, артикулы, четыре текстовых поля и текст первых двух rich-блоков. Лист «Инструкция» объясняет формат.

- Можно оставить только идентификатор и изменяемые столбцы. Отсутствующий столбец не меняет значение.
- Пустая ячейка в присутствующем столбце очищает значение; пустое название отклоняется.
- Неизменённый файл не создаёт правок. Изображения и остальные rich-блоки сохраняются.
- ID или артикул должен однозначно соответствовать существующему товару; противоречащие идентификаторы отклоняются.
- При наличии версии устаревшая строка отклоняется. Без версии сравнивается текущий снимок на момент загрузки; для защиты от старых выгрузок сохраняйте столбец версии.
- Формулы не выполняются и отклоняются при загрузке. Лимиты мока: файл до 10 МБ, до 2 000 строк.
- Новые товары создаются в разделе «Генерация». Изображения и полная структура rich не переносятся через Excel: доступны PNG и JSON из редактора.

Excel — перенос редактируемых текстов, а не полная резервная копия проекта.
Произвольные характеристики и бренд в текущий Excel-шаблон не включены; при импорте они сохраняются без изменений и редактируются на сайте.

## Данные и границы мока

Хранилище: marginpilot.cards.content.v2 в localStorage. При первом открытии переносятся текстовые поля совпадающих исходных товаров из marginpilot.cards.v1; прежний ключ не удаляется. Новые товары и журнал старой версии автоматически не мигрируются.

Генерация детерминированная, по шаблону, без вызова AI. Она демонстрирует сценарий выбора, предпросмотра и сохранения. Фото передаются в запрос и используются в макете, но визуальные свойства товара в моке не распознаются. В режиме «только изображения» описание остаётся шаблонным. Схематичные изображения помечены как условные. Галерея принимает PNG/JPEG/WebP до 2 МБ на файл, максимум 10 изображений. Rich поддерживает до 10 блоков. Это ограничения прототипа, а не полная валидация Wildberries.

При переполнении localStorage появляется предупреждение; последние изменения доступны только до перезагрузки. Серверный проект должен хранить медиа отдельно от JSON карточек. Конфликт версии проверяется внутри текущего repository; синхронизация нескольких вкладок браузера в моке не реализована.

История хранит снимки до/после. Журнал генерации локальный; фоновой очереди, возобновления заданий и реальных вызовов моделей пока нет.

## Интеграция WB

Поисковые запросы доступны через Analytics API для собственного ассортимента при токене категории «Аналитика» и подписке «Джем». [Официальная инструкция](https://dev.wildberries.ru/knowledge-base/articles/019d49a4-0f6a-70bb-a87b-c1237a1a0714). Это не общерыночная база всех ключевых слов.

Токены и обращения к WB должны находиться на сервере. Для Content API нужны сопоставление полей, обязательные характеристики категории, отдельная загрузка медиа и проверка фактического результата публикации. Локальные статусы нельзя напрямую считать статусами WB.

Для rich-контента проверен редактор WB, но публичный метод записи rich через API в этой работе не подтверждён. До проверки сохраняйте самостоятельную структуру блоков и экспорт; не обещайте автоматическую загрузку rich на площадку.

## Проверка и запуск

Запуск сервера описан в корневом README. При работающем сервере на порту 8001:

```powershell
python dashboard/cards/test_content_workspace.py
python dashboard/cards/test_generation.py
python dashboard/cards/test_studio_prompt.py
```

Нужны Python Playwright и Chromium. Проверки используют отдельный браузерный контекст, не меняют данные пользовательского браузера. Покрыты быстрые правки, rich, массовые операции, атомарность, генерация, PNG, настоящий XLSX с ошибками и конфликтами, доступ к поисковой аналитике, сохранение, адаптивность и клавиатура. Скриншоты — в игнорируемом каталоге artifacts.
